# Form Sender

Внутрішня адмін-панель для масової відправки заявок через форму, вказану в `FORM_URL`.

Сервіс не замінює зовнішню форму. Оператор працює в адмін-панелі, а програма по черзі заповнює і відправляє оригінальну форму для кожної цілі.

## Як це працює простими словами

Оператор заходить в адмін-панель і вводить всі дані для відправки. Він вибирає тип цілі, вставляє список доменів, IP або URL по одному в кожному рядку, вибирає тип загрози, пише причину і за потреби додає файл.

Коли оператор натискає кнопку відправки, сервіс ділить список на окремі рядки. Далі він бере першу ціль, відкриває оригінальну форму, знаходить актуальні приховані поля і готує дані для відправки.

Після цього сервіс створює задачу в 2Captcha і чекає, поки капча буде вирішена. Отриманий код сервіс додає до форми і відправляє одну заявку на зовнішній сайт.

Після відповіді сайту сервіс шукає код підтвердження `CF-XXXXXXXX`. Якщо код знайдений, ціль отримує статус успішної відправки. Якщо сталася помилка, вона зберігається біля цієї цілі, щоб оператор розумів, що саме не пройшло.

Після завершення першої цілі сервіс переходить до наступної. Тому список із десяти рядків перетворюється на десять окремих відправок. Всі результати зберігаються в історії, а помилкові заявки можна запустити ще раз.

## Що вміє сервіс

- вибір типу цілі: `Domain`, `IP` або `URL`;
- введення декількох цілей, по одній у кожному рядку;
- вибір `Threat Type`;
- введення `Reason`;
- завантаження JPG, JPEG, PNG або PDF до 2 МБ;
- окрема відправка кожної цілі;
- автоматичне рішення Google reCAPTCHA через 2Captcha;
- отримання коду підтвердження формату `CF-XXXXXXXX`;
- зрозумілий результат для кожної цілі;
- повторна відправка однієї помилкової заявки або всіх помилкових заявок;
- історія відправок і кількість спроб.

## Як працює відправка

Для кожної цілі сервіс окремо:

1. відкриває сторінку зовнішньої форми;
2. отримує актуальний прихований `form_token` і адресу відправки;
3. знаходить ключ reCAPTCHA;
4. створює задачу в 2Captcha і чекає її рішення;
5. формує POST-запит з потрібним полем (`domain`, `ip` або `url`), типом загрози, причиною, згодою з умовами і файлом;
6. відправляє заявку на зовнішній сайт;
7. шукає у відповіді код `CF-XXXXXXXX`;
8. зберігає успішний результат або причину помилки.

Якщо ввести три рядки, сервіс зробить три окремі відправки. CAPTCHA-токен для кожної цілі створюється заново.

## Швидкий запуск через Docker

Потрібні Docker і Docker Compose.

```bash
cp .env.example .env
```

Відкрийте `.env` і вкажіть мінімум:

```env
TWOCAPTCHA_API_KEY=ваш_ключ_2captcha
ADMIN_PASSWORD=пароль_оператора
SECRET_KEY=довгий_випадковий_секрет
```

Запустіть сервіс:

```bash
docker compose up --build
```

Після запуску відкрийте:

<http://localhost:5000>

Вхід виконується через пароль з `ADMIN_PASSWORD`.

## Запуск без Docker

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Після заповнення `.env` завантажте змінні і запустіть застосунок:

```bash
set -a
. ./.env
set +a
python app.py
```

Застосунок буде доступний на <http://localhost:5000>.

## Налаштування

| Змінна | Для чого потрібна | Значення за замовчуванням |
|---|---|---|
| `FORM_URL` | URL зовнішньої форми | `https://linkreclamatiogrwc.uk/` |
| `TWOCAPTCHA_API_KEY` | API-ключ 2Captcha | не задано |
| `ADMIN_PASSWORD` | Пароль адмін-панелі | `admin123` |
| `SECRET_KEY` | Секрет для Flask-сесії | `change-this-secret` |
| `RATE_LIMIT_SECONDS` | Пауза між цілями | `1.0` |
| `CAPTCHA_POLL_SECONDS` | Інтервал перевірки 2Captcha | `5` |
| `CAPTCHA_TIMEOUT_SECONDS` | Максимальне очікування CAPTCHA | `180` секунд |
| `REQUEST_TIMEOUT_SECONDS` | Таймаут HTTP-запитів | `45` секунд |
| `MAX_TARGETS` | Максимум цілей за один запуск | `100` |

API-ключ 2Captcha не потрібно записувати у код або комітити в Git. Для Railway його треба додати у Variables сервісу.

## Сторінки сервісу

- `/` — перенаправлення на вхід або сторінку відправки;
- `/admin/login` — вхід оператора;
- `/admin/sender` — форма масової відправки;
- `/admin` — історія останніх відправок;
- `/admin/logout` — вихід;
- `/healthz` — перевірка, що застосунок працює.

## Результати і повтор

Для кожної цілі зберігається окремий результат:

- `submitted` — заявка відправлена і знайдений код підтвердження;
- `error` — виникла помилка, її текст показується оператору;
- `pending` — заявка була створена, але ще не завершила обробку.

Для рядків зі статусом `error` доступний повтор. При повторі створюється нова задача 2Captcha, а лічильник спроб збільшується.

## Збереження даних

Локально сервіс використовує:

- `data/submissions.db` — база SQLite з історією заявок;
- `uploads/` — завантажені файли.

У Docker Compose ці каталоги підключені як volumes. На Railway для постійного збереження даних потрібно окремо підключити Railway Volume або зовнішню базу/сховище.

## Деплой на Railway

Репозиторій можна підключити до Railway як GitHub repository. Railway сам запускає застосунок через `Procfile`:

```text
web: python app.py
```

У Railway Variables потрібно додати:

- `TWOCAPTCHA_API_KEY`;
- `ADMIN_PASSWORD`;
- `SECRET_KEY`;
- за потреби інші змінні з таблиці вище.

Порт застосунок бере зі змінної `PORT`, яку передає Railway. Перевірити роботу сервісу можна за адресою `/healthz` — у відповідь має прийти:

```json
{"status":"ok"}
```

## Важливі обмеження

- Відправка зараз виконується послідовно в одному запиті, тому під час великого запуску сторінку не потрібно закривати.
- Сервіс приймає максимум `MAX_TARGETS` цілей за один запуск.
- Перевіряється розширення і розмір файлу, але правильність домену, IP або URL перевіряє зовнішній сайт.
- Якщо процес зупиниться під час обробки, для production бажано додати окрему фонову чергу і worker-процеси.
- Не потрібно публікувати `.env` або API-ключ 2Captcha.
